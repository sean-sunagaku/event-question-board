# 仕様と完了条件

## 目的と範囲

2026-10-31の依頼: 公開OSSリポジトリを作成し、Codex Cloud環境を設定し、そのCloud上でUIも含む実装・テスト・3つのGPT Sitesへの公開まで行う。
イベント固有の登録情報を持ち込まず、別のイベントでも手元で実行できる質問・投票ボードにする。

## 利用体験

- 参加者は全質問を閲覧する。質問の承認待ち・管理者だけの非公開質問は作らない。
- 参加者は質問を投稿し、他の質問に投票・投票解除できる。1人の同じ質問への投票は1票。
- 質問一覧は人気順・新着順を切り替えられ、回答済み・強調が分かる。
- Adminは全質問を見て「回答済み」と「強調表示」を切り替えられる。
- 管理操作の結果は参加者にも反映される。ページの手動再読込を毎回要求しない。
- ネットワーク切断・空データ・読み込み・入力エラー・送信中・二重送信を扱う。
- モバイルで質問を読み、片手で投票しやすい、落ち着いた日本語UIにする。
- デモ用のイベントと質問は架空と明示し、実際の参加者の回答を流用しない。

## 3サービスと共通コード

| 単位 | 役割 | 永続データ |
| --- | --- | --- |
| participant | 一覧・投稿・投票。必要なら同一originのBFF | API経由のみ |
| admin | 回答済み・強調。必要なら同一originのBFF | API経由のみ |
| api | API契約・入力検証・認可・質問・投票 | このサービスだけがDBを所有 |

公開GitHubリポジトリは1つ。共有の型・入力検証・UI・ドメイン処理は `packages/` に置く。
各サービスは個別のbuild、起動、ホスティングmanifestを持ち、他サービスの実装コードをコピーしない。
モノレポから各Sites向けの配布物を生成し、公開GitHubの同じcommitへ追跡できるようにする。
ローカルも同じアプリソース・DBマイグレーション・認可処理を使う。環境差分だけ設定する。

## 認証と認可

- 公開する全質問は未認証でも閲覧可能。投稿・投票には安定した利用者識別を必要とする。
- Sitesでは標準のChatGPT認証を使用。Siteごとに異なるユーザーIDを、同一IDと仮定しない。
- フロントからAPIへ利用者情報を渡すときは、サーバーが認証結果から生成した、改ざん・リプレイ対策を持つ情報を使う。
- `x-user-id`、`x-admin`、クライアント指定role、表示名、CORS設定だけを根拠に管理者にしない。
- 参加者側サービスの資格情報で管理操作を行えないよう、API側でcallerと管理者を検証する。
- Adminのホスティングアクセスと、APIの管理者認可は別々に検証する。既定で拒否する。
- サーバーからAPIへの呼出しやBFFにより、ブラウザ間のCookie共有を前提にしない。
- 管理者設定、ローカル認証、Sites認証の使い方と違いをREADMEに書く。開発用認証は本番で必ず無効にする。
- 実装前にSites間のサービスアクセス・公開API・CORS・CSRFを検証し、採用方式とその根拠を `docs/architecture.md` に記録する。

## データと整合性

イベント、質問、投票を扱う。最初は1イベントのデモでもよいが、IDを契約に含め別イベントの質問を混ぜない。
質問本文の長さ・空白・形式をサーバーで検証し、HTMLとして実行しない。
DBに投票の一意制約を置き、同時投票でも重複しないようにする。表示上だけの重複防止で代用しない。
DBの永続化、マイグレーション、架空デモの明示的seed、バックアップと復元の手順を用意する。
本番のリクエスト処理でテーブルを自動作成したり、毎回seedで上書きしない。

## 開発者体験

`npm ci` 後、DB初期化・3サービス起動・typecheck・test・build・E2Eを明示したコマンドで実行できること。
`.env.example` はキー名と安全な例のみ。通常のcloneではSites固有ID・秘密情報なしでローカル開発できること。
Node/npmの対応バージョン、各ポート、ローカル管理者の使い方、トラブル時のログと再実行手順を用意する。
CIは公開リポジトリのcloneから必要な検証を行い、個人アカウントの本番秘密情報を要求しない。

## 範囲に含めないもの

Lumaの登録データ取込み、参加者への招待・メール・SNS告知、課金、AIによる自動回答、質問の事前承認は依頼に含まれない。

## 追加目標: 自己ホスト本番OIDC（2026-10-31）

前回のSites完成条件と公開証拠を保持し、同じparticipant/Admin/API・共通packagesを設定で自己ホスト本番へ切り替える。実IdPのアカウント作成・課金・外部本番への新規公開は不要。検証用Providerは本番IdP運用製品として配布しない。

- [x] AUTH_MODE=oidc/sites/localの薄いアダプター分離。Node本番はOIDCのみ、固定開発ログインとSitesヘッダーを拒否する。
- [x] 一次資料に基づくAuthorization Code＋S256 PKCE。ライブラリでIDトークン署名・issuer・audience・期限・state・nonceを検証する。
- [x] APIで厳密なissuer＋subject allowlistを強制する。メール・role・偽造ヘッダー・参加者資格情報で昇格しない。利用者キーはissuerと認証方式を名前空間化する。
- [x] npmの本番コマンドで3サービスを起動し、API DBと各サービス別セッションDBを永続化する。既存DB migrationを維持する。
- [x] 複数Set-Cookieを個別応答し、サービス固有名のSecure/HttpOnly/SameSite Cookie、CSRF防止、セッション更新/失効/ログアウト/期限を実測する。
- [x] 設定未完・信頼しないproxy/host/origin・HTTPのIdP接続は既定拒否する。外部domain/IdP/secretは設定だけで指定する。
- [x] 実Provider・本番モード3プロセス・実SQLiteをTLS検証有効のHTTPSで接続し、ブラウザのログイン→投稿/投票/解除→Admin操作→自動反映→ログアウトを確認する。
