# Codex Cloudへの実行指示

この文書は実装タスクの入力。ユーザーは公開OSSリポジトリ・Cloud設定・UIを含む実装・テスト・3つのGPT Sitesへの公開まで依頼済み。
計画だけ、ローカルだけ、UIだけで終了せず、目標を作成して最後まで進める。

## 最初に

1. `AGENTS.md`、`docs/spec.md`、`docs/progress.md` を読む。
2. 利用可能なSitesスキルとツールを確認する。Sites環境で提供されるstarter・build・配布方法を使う。
3. Cloud環境でGitHubのこのモノレポがcheckoutされていること、依存インストール、実行ツール、ブラウザ、Sites接続を確認する。
4. APIの認可とSites間通信を小さく検証する。IDのSite間共通性やCookie共有を仮定せず、実測した構成を採用する。

## 実装

`apps/participant`、`apps/admin`、`apps/api` と共通 `packages/` を実装する。
共通ソースをworkspace参照し、独立した3サービスとして起動・build・deployできる形にする。
質問はすべて公開。参加者は投稿・投票・解除、Adminだけ回答済みと強調を変更できる。
DBに保存し、投票一意性、API認可、入力検証、エラー状態、画面への更新反映を完成させる。
日本語UIを作り、PC・スマートフォンの幅で実操作・目視を行う。
画像は体験の理解に必要な場合だけ生成・使用し、画像制作自体を目的にしない。

## 検証と公開

ローカル起動手順、DB初期化、typecheck、test、build、3サービスのE2E、CIを整える。
公開環境に秘密情報や個人情報を持ち込まず、Sitesの認証・環境変数管理を使う。
各アプリを別Siteとして登録し、IDを即時保存する。IDが既存なら再利用する。
APIと参加者は必要な公開アクセス、Adminは本人向けアクセスを設定し、APIの権限強制も維持する。
公開GitHubを正本とし、同じcommitからSites配布物を生成する。ホスティング用ソースremoteと公開GitHubを混同しない。
Sitesの標準手順で保存済みversionをdeployする。期待URL・作成済みSite・PRだけを公開完了の証拠にしない。
公開された3サービスで、参加者の投稿・投票とAdminの回答済み・強調、一般利用者の管理操作拒否、更新反映を検証する。
必要な修正を続け、GitHubへpush、CI確認、PR作成・マージまで進める。

## 完了時に残す情報

`docs/progress.md` を更新し、仕様の受け入れ条件を証拠とともにチェックする。
Cloud環境・Cloudタスク、GitHubのcommitとPR、3つのSitesのURL・ID・version、実施したテストと結果、残作業を記録する。
認証情報やアクセス用トークンを記載しない。
必要なツール・接続・権限がない場合は、そこで可能な独立作業を進め、具体的な障害と再開手順を残す。完了とは報告しない。
